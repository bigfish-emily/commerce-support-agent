# 使用手册

## 产品入口

启动服务后打开 `http://127.0.0.1:8000/customer`。页面会先展示当前账号名下的订单、在途数量和待留意订单。用户可以直接问“我有哪些订单还在运输中”或“我喜欢什么样的产品”，也可以从订单卡片的原生操作入口开始处理；待发货订单提供取消/改地址，已送达订单提供退款/售后，已取消订单提供退款进度/发票。后端仍会按订单事实和政策二次校验。自由描述的问题则交给 Agent 识别意图、寻找所需事实并协调后续步骤。用户不需要手动输入订单号。“订单小结”只总结当前账号可见订单，不推断个人敏感属性或长期偏好。

本地默认账户为 `demo-customer`，包含 5 笔公开历史订单。`X-Demo-Customer` 仅用于本地演示不同账户；生产接入由 BFF 从登录会话/JWT 解析用户身份与可访问订单，浏览器请求体中的 `user_id` 不参与客户接口的身份判定。

涉及业务写入的请求会生成申请：客户立即看到受理状态，后台审核完成后页面会自动刷新进度。应用没有真实支付或退款能力，所有写动作仅作用于本地业务服务。

打开 `http://127.0.0.1:8000/review` 进入审核台。默认本地凭证为 `local-review-demo`，可用 `REVIEW_API_TOKEN` 覆盖。审核人员可查看客户对话和订单事实、接手会话、使用可编辑的 AI 回复草稿，以及批准或驳回待审核申请。

`/technical` 保留给工程检查；客户页不展示 trace、工具名称、风控标签或内部政策字段。

## 启动与模型

```bash
uv sync --extra dev
uv run uvicorn app.main:app --reload
```

未配置 key 时，应用使用本地 fallback，适合测试流程。配置 OpenAI-compatible key 后会启用真实模型：

```text
OPENAI_API_KEY=your-key
OPENAI_BASE_URL=https://api.deepseek.com
OPENAI_MODEL=your-chat-model
```

部分兼容网关不稳定支持原生 structured output；本项目会改用“JSON 文本 + Pydantic 校验”的兼容路径。

## 推荐演示

1. 在客户页点击“查看在途订单”。该动作不经过 LLM planner，系统以当前登录用户的订单集合调用确定性只读工具。
2. 从一笔订单卡片点击“申请退款”，或在对话中描述问题。订单选择作为结构化页面上下文传给后端，AfterSalesCase 会收集订单事实和政策依据；高风险请求显示“申请已受理，等待审核”。
3. 打开审核台，选择该会话，阅读订单事实和申请依据；点击“接手会话”后，客户新消息直接进入人工会话。
4. 点击“生成回复建议”，编辑后发送；或批准/驳回待审核申请。客户页会轮询并显示最新结果。

内部 trace、case 指标与 API 文档位于 `/observability/*` 和 `/docs`，审核访问需要 review token。

# Support FAQ

## Refund Status FAQ

Customers often ask whether a refund is already completed. The Agent must not
claim that a refund has been completed unless the refund or payment tool returns a
confirmed refund id. If only a support case has been created, explain that the case
is under review and provide the case id.

If the customer asks why the refund is still pending, the Agent should check order
status, payment records, and after-sales case history before answering. Missing
order id, missing payment facts, or ambiguous customer identity should lead to a
clarification question.

## Return Label FAQ

For product-quality, wrong-item, missing-item, or damaged-package complaints, the
Agent may prepare a return or inspection case. A return label can be promised only
after the downstream returns tool confirms eligibility and label creation. If the
order is not found or the item is not eligible, the Agent should explain the
specific missing requirement.

## Delivery Complaint FAQ

When customers report that a package has not arrived, the Agent should distinguish
between pending delivery, confirmed delay, delivered-late, and already delivered.
Use logistics and order facts instead of guessing from user language. For severe
delay or low review recovery cases, prepare an after-sales case and avoid direct
cash-refund promises before approval.

## Complaint Escalation FAQ

Escalate to a human reviewer when the customer reports repeated failed contacts,
legal threats, safety concerns, high-value orders, repeated compensation requests,
or conflicting order/logistics facts. The escalation summary should include order
facts, policy sections, verifier flags, and the exact customer request.
